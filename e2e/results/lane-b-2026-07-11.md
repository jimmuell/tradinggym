## Foundation graduation VERIFY (positive half, from zero)

**Fix under test:** `f3263d1` — `Foundation.tsx` now derives the module count from
`useCompletedLessonIds()` (server `lesson_progress`) instead of `localStorage['completedLessons']`.
Both the write (`useMarkLessonComplete`) and the read (`useCompletedLessonIds`) hit `lesson_progress`.

**Bundle confirmation (precondition):** the fixed page issues `GET /rest/v1/lesson_progress?select=lesson_id…`
on load; the old bundle read localStorage and never made that request. The VERIFY spec waits for that
request before asserting — it fired, so the **new bundle is live**. (A pass is only possible on the
fixed bundle: on the old build a fresh account shows "0 of 5" and the spec fails at the count/enable
step.)

**New guard:** `e2e/foundation-graduation-fresh.spec.ts` — fresh signup → 5 modules → assessment →
graduate → hard reload. This is the POSITIVE half that never existed; `foundation-gate.spec.ts` is the
NEGATIVE half (gate rejects the unqualified). Complements. The positive half is the one whose absence
let the bug live Jul 7–11 (every account we tested was already graduated).

**Observed, artifact-backed:**
- Live Foundation lesson set = **5** (`f1_candles, f2_structure, f3_sessions, f4_risk, f5_plan`) — DB query.
- Fresh account: `tier_state='foundation'`, `lesson_progress` rows = 0 at start (authed supabase-js).

  DISABLED, with `localStorage['completedLessons'] === null`.

  `completedLessons*` keys and hard-reloaded → "5 of 5 modules complete" + Take Assessment ENABLED.
- Assessment passed via `submit_quiz_attempt` (server-graded) → PASSED badge + "1 / 1 correct"
  (at the time of THIS run the served assessment was a **1**-question stub — later found to be a
  shadow bug and fixed; re-verified against the real 10-question gate in **Assessment VERIFY** below).
- Risk-ack (`update_own_profile`) → `graduate_foundation` → **`tier_state='tier1'`** (server).
- Simulator canvas visible (no "Simulator Locked"); Strategies open ("Browse proven trading strategies");
  Analytics open (no "Analytics Locked"); Tier 1 open (no "Complete Foundation to unlock").
- Hard reload after graduation → "5 of 5" + gates still open + `tier_state='tier1'` (persisted).

**Teeth — proven empirically (not just by construction).** A throwaway variant (not committed)
completed all 5 modules for real (DB holds 5 rows), then intercepted only the `lesson_progress` GET →
`[]` and reloaded: the page collapsed to **"0 of 5 modules complete"** and re-disabled Take Assessment,
and "5 of 5" was absent. So the count tracks the DB read and nothing else — a non-DB source (the old
bug) could not produce the fresh-account "5 of 5", and the committed assertion goes red the moment the
DB read stops backing it. Run: `2 passed (17.3s)`; teeth account below.

## Assessment VERIFY (real 10-question gate)

**What was wrong:** three published platform quizzes existed for `module='foundation'`;
`useQuizByModule()` orders `created_at DESC LIMIT 1`, so from May 9→Jul 11 the app served a
**1-question** stub as the graduation gate (1 correct = 100% ≥ 80%). The real **10-question**
assessment (`06d7aff8…`, Apr 22) was buried, not gone. Fixed before this run: stubs unpublished
(not deleted — `quiz_attempts` reference them), and a partial unique index
`quizzes_one_published_platform_per_module` now blocks a duplicate publish. This run confirms the
**running app** serves the real assessment (data-right vs product-does-right).

**Observed, artifact-backed (`e2e/foundation-graduation-fresh.spec.ts`, live, green):**
- DB (same query as `useQuizByModule('foundation')`): served quiz `06d7aff8-85ce-41e9-81dc-88dad266a897`,
  **10 questions**, `pass_threshold = 80`; **exactly one** published platform foundation quiz.
- New shadow guards in the spec (both DB-derived, no hardcoded 10):
  - `expect(publishedQuizzes.length).toBe(1)` — defence-in-depth behind the DB index.
  - UI assertion `Question 1 of {expectedQuestionCount}` — the running app must render as many
    questions as the single published row; a stub leaking through goes red here.
- All **10** questions answered through the UI; `submit_quiz_attempt` (server-graded) returned
  PASSED with "10 / 10 correct" (≥ 80%); risk-ack → `graduate_foundation` → `tier_state='tier1'`;
  Simulator/Strategies/Analytics unlocked + Tier 1 open; **survived a hard reload**.
- Passed legitimately — RPC not bypassed, threshold not weakened.
